## M0 — architecture decisions

These are recorded here; the ADRs go deeper.

1. **Workspace layout.** pnpm workspaces. Root has dev tooling (lint, typecheck, smoke, docs-check, boundary-check). Apps are `server/api`, `server/realtime`, `server/workers`, and the pure `packages/npc-brain`. Tooling is `tools/{bots,contract-check,econ-sim,scripts}`.
2. **Layering enforced by ESLint and a CI script.** Domain (server/shared, packages/*) cannot import transport. Enforced by `no-restricted-imports` and `tools/scripts/boundary-check.ts`.
3. **Money is a value object.** `Cents` (bigint), `TokenAmount` (bigint base units). No `number` for money in domain code. No floating-point math. Decimal math via `decimal.js` is allowed at the price-feed boundary only.
4. **Errors are a typed domain hierarchy.** Mapped to contract error codes at the transport boundary. Throwing domain errors only; no `throw new Error("…")` in business logic.
5. **Composition roots.** One per process: `server/api/main.ts`, `server/realtime/main.ts`, `server/workers/main.ts`. Constructor injection, no service instantiates its own DB/Redis/Solana/LiveKit/clock/random.
6. **Idempotency middleware.** Single implementation, applied to every POST/PUT/PATCH/DELETE. Key in Redis + Postgres, 24-hour TTL, replays first response. Same key with a different body hash returns `VALIDATION_FAILED`. Concurrent requests with the same key are serialized to prevent double-execute.
7. **Dev auth.** `POST /v1/auth/dev` only when `ENABLE_DEV_AUTH=true`. Build hard-fails at startup if `ENABLE_DEV_AUTH=true && (NODE_ENV=production || APP_ENV in {staging, prod})`. Test covers this.
8. **Bot population (mock profile).** `tools/bots/world.ts` runs 20 bots in Timeline Square: real keypairs, real SIWS, real rooms, walking, emoting, chatting, trading. The `mock` profile starts the real stack with `ENABLE_DEV_AUTH=true` plus the bot population service.
9. **NPC brain placement.** `packages/npc-brain` is a pure TypeScript library (no I/O, no DB, no transport). Each venue room instance runs its NPCs at 1 Hz. Workers handle global triggers (launches, liquidations, mood, ORE motherlode) and publish them on Redis pub/sub. Rooms consume via the `EventPublisher` interface.
10. **Market engine.** Single writer per coin via a Redis lock. BullMQ repeatable job per coin runs the tick loop. Seeded RNG per coin. Ticks every 2 s. Bonding curve (constant-product with virtual reserves) graduates to an `x·y=k` pool at the configured market cap. Hidden arc is server-only.
11. **Price feeds.** Pyth Hermes primary, CoinGecko fallback for SOL 24h change (Market Mood). Jupiter price API primary, CoinGecko fallback for USDC/SOL/SKR/ORE quotes. Cache and timestamp every quote. Quote locked into the intent at creation. If a feed is down for a new intent, return `503 PRICE_FEED_DOWN` rather than guess.
12. **Cash units.** int64 cents. $500 = 50000. Coin units are int64 base units with 6 decimals. Token amounts are strings in base units.
13. **ORE on mainnet.** ORE read and stake instructions run on mainnet even on staging. Tests that move real mainnet value require `RUN_MAINNET_TESTS=1`. Defaults off. Stake transaction simulation runs by default; only send is gated.
14. **Push and LLM.** Behind feature flags that default off until verified. `PUSH_ENABLED` (default false until Seeker Google Play services confirmed), `LLM_ENABLED` (default false), `X_LINK_ENABLED` (default false until credentials present).
15. **Spec owner conflict on IDs.** `spots.json`, `anims.json`, `sfx.json` are FE-owned; `mini_games.json` is FE-built. Provisional versions ship so move validation and shift scoring work. Each provisional file is marked `"_provisional": true, "_owner": "FE"`. Additions only after the teammate signs off; never changes to existing IDs.
