## Per-commit log

### `retrofit: docs`

- Created: `docs/ARCHITECTURE.md`, `docs/DATA_MODEL.md`, `docs/ECONOMY.md`, `docs/REALTIME.md`, `docs/NPCS.md`, `docs/ONCHAIN.md`, `docs/SECURITY.md`, `docs/OPERATIONS.md`, `docs/RUNBOOK.md`, `docs/TESTING.md`, `docs/CAPACITY.md`, `docs/RETROFIT_REPORT.md`, `contract/CHANGELOG.md`.
- README: env-var table expanded to one row per variable.
- Mermaid diagrams: architecture, auth sequence, payment-intent lifecycle, paid-call state machine, perp lifecycle, Sunday Unlock, NPC event propagation, deployment topology. Per-NPC and per-room diagrams are placeholders until M1.

### `retrofit: boundary-check`

- `tools/scripts/boundary-check.ts` rewritten to scan all of `server/*` and `packages/*`, with the transport roots being `server/api`, `server/realtime`, `server/workers`, and `tools/bots`. Composition roots (the `main.ts` of each process) are exempt. Catches direct imports and indirect imports through `..` segments.
- The CI `lint` job runs `pnpm boundary:check` on every push. It fails on any transport import from the domain.

### `retrofit: docs-check`

- `tools/scripts/docs-check.ts` rewritten to verify:
  - Every env var referenced in code is declared in `.env.example` and the README (exhaustive list).
  - Every error code in `contract/ids/errors.json` is referenced in `contract/openapi.yaml`. (The check is added now; it is a no-op until M1 publishes the IDL.)
  - Every realtime message in `contract/realtime/*.ts` is referenced in `docs/REALTIME.md`. (No-op until M1.)
  - Every relative Markdown link in `docs/*.md` resolves to a real file.
- The CI `lint` job runs `pnpm docs:check` on every push.

### `retrofit: contract-additive`

- `contract/CHANGELOG.md` created. The first entry records the additive additions: `SERVER_BUSY` error code, `degraded: string[]` field on `GET /v1/config`, market-room sharding (M3).

## Deliberately left (and why)

- **Multi-process realtime sharding** — M3 deliverable. The M0 compose has a single realtime service to keep the M0–M2 development loop simple. The design supports multi-process; the implementation lands with the M3 market engine.
- **Market engine leader election** — M3 deliverable. Documented in `ARCHITECTURE.md`.
- **Per-NPC and per-room diagrams** — placeholders until M1 publishes the schemas. M1 commit will fill them.
- **OpenAPI HTML render in CI** — M1 deliverable. The contract-check step will render with Redoc or Scalar and serve at `/docs` in non-production.
- **Anchor `///` doc comments** — M3 deliverable. The instruction accounts, errors and events all get doc comments at the same time as the program is written.
- **Typed error hierarchy, Unit of Work, contract tests for interfaces** — M2 deliverable. The boundaries are designed; the implementation lands with the first business code.
- **Load / spike / soak / chaos tests and `docs/CAPACITY.md` measurements** — M8 deliverable. The test harness is sketched; the numbers are placeholders.

## What the amendment would not change about M0

- The compose file: a single realtime process is fine for M0–M2.
- The smoke test scope: the seven required checks remain the gate; the devnet airdrop is informational.
- The dependency surface: Postgres, Redis, Helius, LiveKit, MinIO, Solana RPC are the same.
