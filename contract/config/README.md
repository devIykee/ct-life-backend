config
====

Every JSON file in this directory is part of the contract. The companion `*.schema.json` describes each file. The `contract-check` tool runs the schema validator and fails the build if any file is invalid.

Files:

| File              | Contents                                                                                                                                 | Unit notes                                                                                                                        |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `economy.json`    | Top-up packs, currency decimals and bonuses, rent, tax brackets, lottery outcomes, Sunday Unlock + Monday Reset cron.                    | `cashCents` is int64 cents. `topUpCapCentsPerDay` is 100 USDC. SKR decimals come from the on-chain mint.                          |
| `needs.json`      | Decay per real hour for each need, the actions that raise each need, the list of club venues.                                            | Decay is per real hour; tests assert the formula `decayPerHour * hoursElapsed` against the read result.                           |
| `skills.json`     | The six skills, XP curve, leverage cap by Trading level, tribe bonus leverage, skill gates per career.                                   | Leverage cap formula: `leverageByTradingLevel[trading-1].leverage + tribeBonusLeverage[tribe]`.                                   |
| `lottery.json`    | Weights for the three birth outcomes and the debt repayment terms.                                                                       | `seeker` weight is added only for verified Seeker wallets. The remaining weight is split between `insider` and `exit_liquidity`.  |
| `careers.json`    | 14 careers x 5 levels. Each level has pay, shift length, XP, and the miniGameId that runs it.                                            | 3 active in Phase 1 (`discord_mod`, `junior_analyst`, `kol_engagement`); the other 11 unlock in Phase 4.                          |
| `gigs.json`       | Side gigs and their pay formulas.                                                                                                        | Formulas are arithmetic expressions evaluated server-side; the variables are skill values.                                        |
| `businesses.json` | Business cost, income range, and bad-day chance.                                                                                         | `badDayMultiplier` is the fraction of the lower bound the player receives on a bad day.                                           |
| `market.json`     | Tick length, launch interval, curve parameters, outcome mix, fees, EV test tolerance.                                                    | Outcome mix must sum to 100. EV test asserts that `evAfterFees <= 0` within the tolerance.                                        |
| `events.json`     | Server events, their minimum interval, max concurrent, and effects.                                                                      | The Town Crier line and City broadcast are produced from the same event row.                                                      |
| `meta.json`       | The Weekly Meta rotation (seven slots, one per day).                                                                                     | The rotation engine reads the entry for `weekday % 7` at every Sunday Unlock.                                                     |
| `npc_lines.json`  | 30-60 lines per Phase 1 archetype. `{slots}` are filled from `lineParams` at render time.                                                | Lines NEVER attribute to real people. The `doomposter` archetype never uses the word `jeet` (sensitive per the spec).             |
| `leagues.json`    | League tiers, min net worth to enter, max members, promote target.                                                                       | Promotion evaluated at season rollover.                                                                                           |
| `ads.json`        | Ad placement kinds, term lengths, USDC prices, creative constraints.                                                                     | Creative is EXIF-stripped, re-encoded to PNG/JPG, max 1 MB.                                                                       |
| `ore.json`        | Miner tier thresholds, board cache interval, max round age.                                                                              | Tiers are derived from the player's ORE balance and the `["stake", user]` PDA.                                                    |
| `casino.json`     | The Rug Room: stake limits, slots reel weights and paytable (with the computed RTP), crash growth, coinflip payout and head-to-head cut. | Multipliers are plain numbers (2 decimals); caps are env settings. `contract:check` recomputes the slots RTP and requires 94-96%. |

The schema validator (`tools/contract-check/schema-validate.ts`) loads every `*.schema.json`, compiles the corresponding JSON file, and fails the build on any error. The CI `contract-check` job runs this on every push.
